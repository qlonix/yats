# YATS 操作マニュアル

YATS (Yet Another Touchpad Shortcut) の操作マニュアルです。
タッチパッドに触れながら（またはカーソルを動かした直後に）キーを押すと、マウスクリックやキーマクロ、ウィンドウ操作などを実行できます。キーボードのホームポジションから手を離さずにポインティング操作を行うためのツールで、Sony CSL の [ThumbSense](https://www.sonycsl.co.jp/projects/thumbsense/) に強く影響を受けています。

> 📷 スクリーンショット差し込み箇所は `📷` で示しています。画像は `docs/images/manual/` に置いてください。

---

## 1. 動作の仕組み

YATS は「ポインティング中である」という状態を検出している間だけ、特定のキーをマウス操作などに変換します。

ポインティング状態の検出には2つの方式があります。

| 方式 | 条件 | 特徴 |
|---|---|---|
| 接触検出 (Contact) | タッチパッドに指が触れている間 | カーソルが静止していても発火する。ThumbSense と同じ方式 |
| 移動検出 (Movement) | カーソルが動いてから Release Delay 以内 | マウスやトラックポイントなど、あらゆるポインティングデバイスで使える |
| 自動 (Auto) | 上記のどちらか | 接触検出と移動検出の併用 |

方式は設定画面の **Trigger Detection** で切り替えます（第6章）。既定は Linux が接触検出、Windows が移動検出です。Windows で接触検出を使うには Precision Touchpad (PTP) が必要です。

## 2. 動作環境

| 項目 | Windows | Linux |
|---|---|---|
| OS | Windows 10 / 11（64bit） | 64bit ディストリビューション（glibc 2.35 以降。Ubuntu 22.04 以降相当） |
| アーキテクチャ | x86_64 | x86_64 |

## 3. インストール

### 3.1 Windows

[Releases](https://github.com/qlonix/yats/releases) からインストーラー（`YATS_<バージョン>_x64-setup.exe`）をダウンロードして実行してください。ユーザー単位でインストールされるため、管理者権限は不要です。

> [!NOTE]
> 本ソフトはデジタル署名を施していないため、Windows SmartScreen の警告（「Windows によって PC が保護されました」）が表示されることがあります。続行するには「詳細情報」をクリックし、「実行」を押してください。

### 3.2 Linux

[Releases](https://github.com/qlonix/yats/releases) から `.deb` パッケージ（Debian / Ubuntu 系）または `.AppImage` をダウンロードしてください。

```bash
sudo apt install ./YATS_<バージョン>_amd64.deb
```

#### 必須要件（Linux）

キーボード入力の監視と仮想デバイスの作成（リマップ）に、デバイスアクセス権限が必要です。

1. **ユーザーを `input` グループに追加**し、一度ログアウトして再ログイン（または再起動）してください。

   ```bash
   sudo usermod -a -G input $USER
   ```

2. **ウィンドウ操作機能**（閉じる、最大化など）には `xdotool` と `wmctrl` が必要です。

   ```bash
   sudo apt install xdotool wmctrl
   ```

権限が不足していると、キーのリマップが一切機能しません。まずここを確認してください（第10章）。

## 4. 基本的な使い方

1. YATS を起動します（設定画面が開きます。そのまま常駐します）。
2. タッチパッドに親指を触れたまま（接触検出の場合）、割り当てたキーを押します。
3. キーに割り当てたアクション（クリックなど）が実行されます。

操作のコツ:

- **クリック**: 触れながらクリック用のキーを押して離します。
- **ドラッグ**: クリック用のキーを押したまま、もう一方の指（または同じ親指）でタッチパッドを滑らせ、目的の場所でキーを離します。
- **スクロール**: スクロール用のキーを押したままタッチパッドを上下に滑らせます。カーソルはその場に固定され、指の動きがスクロールに変換されます。
- **ウィンドウドラッグ**: Window Drag 用のキーを押したままタッチパッドを滑らせると、カーソル下のウィンドウが移動します。

一時停止したいときは、タスクトレイ（システムトレイ）の YATS アイコンのメニューから一時停止／再開を切り替えます。一時停止中はキーが通常のキーとしてそのまま入力されます。

## 5. 設定画面

設定は変更すると即座に保存・反映されます（保存ボタンはありません）。

### 5.1 ヘッダーの設定項目

| 項目 | 説明 |
|---|---|
| Run on Startup | OS の起動時に YATS を自動起動します |
| Release Delay | トリガーが有効な猶予時間（ms）。接触検出では「指を離してから」、移動検出では「カーソルが止まってから」の猶予として働きます（第6章） |
| Trigger Detection | 検出方式の切り替え。Contact (Touchpad) / Movement (Any Device) / Auto (Both)（第6章） |
| Palm Rejection | パームリジェクション（タイピング中の誤発火防止）の有効／無効（第8章） |
| Palm Delay | Palm Rejection が有効なときに表示されます。最後の打鍵からこの時間内のキー押下をトリガーとして扱いません（第8章） |

画面にはタッチ状態のインジケーターも表示され、ポインティング状態が検出されている間は点灯します。検出の確認に使えます。

- **Key**: 対象のキー
- **Type**: アクションの種類（第7章）
- **設定欄**: アクションの種類に応じた詳細設定（ボタンの種類、スクロール感度、マクロの記録など）
- 行の削除ボタンで割り当てを解除できます
- 新しいキーを追加するには、表の追加行でキーを押して登録します

## 6. トリガー検出方式（Trigger Detection）

### 6.1 Contact (Touchpad) — 接触検出

タッチパッドへの接触そのものを検出します。指が触れている間はずっと有効なので、カーソルが完全に止まっていてもキー操作ができます。指を離した後も、Release Delay の間は有効です（離した直後の押し間違いを拾うための猶予です）。

- Linux: 標準の evdev 経由で検出するためベンダー非依存です（Synaptics / ALPS 以外でも動作します）
- Windows: Precision Touchpad 搭載機種でのみ使えます

### 6.2 Movement (Any Device) — 移動検出

カーソルが動いてから Release Delay 以内のキー押下をトリガーとします。タッチパッドでなくても、マウス、トラックポイント、その他のポインティングデバイス全般で使えます。完全に止まった状態からの押下は発火しません。

### 6.3 Auto (Both) — 自動

接触検出と移動検出の併用です。タッチパッドでもマウスでも、その場で使える方で発火します。

### 6.4 Release Delay の考え方

Release Delay（既定 200ms）は「ポインティングが終わってから、どれだけの間トリガーを受け付けるか」です。

- 短くすると: 誤発火は減りますが、操作がシビアになります
- 長くすると: ゆったり操作できますが、ポインティング直後の通常入力を拾いやすくなります

移動検出でマウスを使う場合、手がマウスからキーボードに戻る時間を考えると、既定より長め（400〜600ms 程度）が使いやすいことがあります。

## 7. アクション一覧

キーには以下のアクションを割り当てられます。

| アクション | 説明 |
|---|---|
| Single Click | マウスボタンのクリック（Left / Right / Middle）。キーを押している間ボタンが押下され、離すと解放されます（ドラッグ可能） |
| Double Click | マウスボタンのダブルクリック（Left / Right / Middle） |
| Scroll | キーを押している間、タッチパッド（やマウス）の動きをスクロールに変換します。感度をキーごとに設定できます |
| Key Macro | 記録したキー入力の列を送信します（下記） |
| Window Control | カーソル下のウィンドウを Close（閉じる）/ Maximize（最大化・復元）/ Minimize（最小化）します |
| Window Drag | キーを押しながらポインタを動かすと、カーソル下のウィンドウをドラッグ移動します。タイトルバー以外をつかんでも移動できます。最大化されているウィンドウは復元してから移動します |
| Browser Back | ブラウザの「戻る」（Windows は VK_BROWSER_BACK、Linux は Alt+← を送信） |
| Browser Forward | ブラウザの「進む」（Windows は VK_BROWSER_FORWARD、Linux は Alt+→ を送信） |

### 7.1 キーマクロの記録

Key Macro を選ぶと記録用の操作が表示されます。記録を開始して実際にキーを押すと、その入力がステップとして記録されます。修飾キーとの組み合わせ（Alt+← など）や、複数ステップの連続入力も記録できます。

## 8. スクロールの調整

スクロールは「どれだけ指を動かしたら、どれだけスクロールするか」を速度ベースで変換します。ゆっくり動かせば細かく、速く動かせば大きくスクロールします。

### 8.1 キーごとの設定

スクロールアクションには、キーごとに感度（Sensitivity）を設定できます。

### 8.2 Scroll Tuning（カーブ編集）

Scroll Tuning を開くと、入力速度（横軸）→出力速度（縦軸）の変換カーブをグラフで編集できます。

> 📷 `06-scroll-tuning.png` — Scroll Tuning のカーブ編集画面

- **カーブの編集**: 点をドラッグしてカーブの形を変えます。直線に近ければ等速、立ち上がりを急にすれば速い動きに強く反応します
- **Min / Max Scroll Output Speed**: 出力軸（縦軸）の範囲です。変更するとカーブが形を保ったまま伸縮します
- **Max Input Speed**: 入力軸（横軸）の上限です。変更するとカーブが形を保ったまま伸縮します。初期値は接続中のモニタ幅から自動決定されます（幅×3/秒）。自分のいちばん速いフリックの 1.2 倍程度に合わせると、カーブ全体を使い切れます
- **Natural Scroll Direction**: スクロールの向きを切り替えます（指の動きと画面のスクロール方向の関係）
- **ライブマーカー**: 調整中に実際にスクロールすると、現在の速度に対応する点がグラフ上にリアルタイムで表示されます

カーブ使用時、Scroll Speed の 25 が等倍（カーブの出力をそのまま使う）です。

### 8.3 送信方式（Linux）

Linux では、スクロール対象のアプリによって送信方式が自動で切り替わります。ブラウザには高解像度のホイールイベントで滑らかに、それ以外のアプリにはボタンイベントで確実に送ります。利用者が意識する必要はありません。

## 9. パームリジェクション

タイピング中、手のひらがタッチパッドに触れていると、打鍵がトリガーとして誤発火することがあります。パームリジェクションはこれを防ぐ仕組みです。ヘッダーの **Palm Rejection** で有効／無効を切り替えます。

### 9.1 Palm Delay

最後の打鍵から Palm Delay（既定 500ms）の間は、キー押下をトリガーとして扱いません。タイピングの合間の誤発火を防ぎます。

- 誤発火が多い → 長くする（例: 800ms）
- 打鍵直後の操作が食われる → 短くする

### 9.2 タイピングモード（Linux）

Palm Delay だけでは、長文入力中の「考える間」（数秒の無打鍵）で時間切れになり、誤発火が抜けることがあります。タイピングモードはこれを補います。

- **突入条件**: タッチパッドに触れながら、間隔 1.5 秒以内の打鍵が 8 回以上、かつ 3 秒以上継続
- **動作中**: トリガーキーも通常のキーとして通します
- **解除条件**: カーソルを大きく動かしてから押したとき／接触が終わって打鍵も止んだとき／10 秒間打鍵がないとき

短いコマンド入力ではモードに入らないため、ターミナル操作などは妨げません。

### 9.3 プラットフォームごとの判定材料

- **Windows**: Precision Touchpad が接触ごとに付ける Confidence（本物の指かどうかの確信度）を使います。手のひらのような接触は Windows 自身もポインタ操作から除外するため、誤発火は起きにくい構造です
- **Linux**: evdev には Confidence 相当の情報がないため、接触面積の生値による手のひら判定（大きい接触は手のひらとみなす）に、Palm Delay とタイピングモードを組み合わせています。発展途上の領域です

### 9.4 OS 側の「タップでクリック」について（Linux）

Linux では、タイピング中に置いた手のひらの動きを libinput が「タップ」と判定し、テキストのキャレットが飛んで文字入力が化けることがあります。これは YATS のトリガーとは別経路の現象です。YATS の利用時は、OS 側の「タップでクリック」を無効にするか、「入力中はタッチパッドを無効にする」（dwt）の併用を推奨します。Windows では Confidence のない接触はタップとして扱われないため、この問題は起きません。

## 10. トラブルシューティング

### 10.1 何も発火しない

- **一時停止になっていないか**: トレイのメニューで再開してください
- **検出方式とデバイスが合っているか**: Contact モードではマウスは使えません。マウスで使いたい場合は Trigger Detection を Movement か Auto にしてください。逆に Windows で Contact を使うには Precision Touchpad が必要です
- **タッチ状態インジケーターが反応するか**: 設定画面のインジケーターで、触れる／動かすに反応するか確認してください。反応しない場合はデバイスが検出されていません
- **Linux の権限**: `input` グループへの追加と再ログイン（第3章）が済んでいるか確認してください。権限がないとデバイスを監視できず、リマップが一切効きません
- **Palm Delay の直後ではないか**: 打鍵直後は Palm Rejection が働きます。少し待ってから操作してみてください

### 10.2 タイピング中に誤発火する・文字入力が化ける

- Palm Rejection が有効か確認し、Palm Delay を長くしてみてください（例: 800ms）
- 長文で抜ける場合はタイピングモード（第9章）が働くまで打ち続ける必要があります（突入には数秒かかります）
- キャレットが飛んで文が入れ替わるような化け方は、OS 側の「タップでクリック」が原因のことがあります（第9.4節）。Linux ではタップでクリックを無効にしてみてください

### 10.3 意図した操作が食われる（発火しないことがある）

- Palm Delay が長すぎると、打鍵直後の意図した操作も抑止されます。短くしてみてください
- Release Delay が短すぎると、ポインティングからキー押下までの間に時間切れになります。長くしてみてください（特に移動検出＋マウス）

### 10.4 スクロールが動かない・おかしい

- スクロールキー押下中にカーソルが固定されているのにスクロールしない場合、対象アプリ側で受け付けていない可能性があります。別のアプリでも試してください
- 速すぎる／遅すぎる場合は、キーごとの感度か Scroll Tuning のカーブ（第8章）で調整してください
- Linux の移動検出（Movement / Auto）でマウスを使う場合、マウスの evdev デバイスが監視対象になっている必要があります。通常は自動検出されます

### 10.5 ウィンドウ操作が効かない（Linux）

- `xdotool` と `wmctrl` がインストールされているか確認してください
- Wayland セッションではウィンドウ操作は動作しません（X11 セッションを使ってください）
- ウィンドウマネージャによっては、ドラッグ中のウィンドウを画面内に収まるよう制限します（例: Cinnamon）。これは WM 側の仕様で、画面外へはみ出す移動はできません

### 10.6 監査ログで確認する

YATS は動作の監査ログを残しています。発火したトリガーは `[TRIGGER]`、パームリジェクションで抑止された場合は `[PALM]` の行に理由付きで記録されます。「発火しない／誤発火する」の切り分けに役立ちます。

| OS | ログの場所 |
|---|---|
| Linux | `~/.local/share/com.yats.app/logs/hardware_audit.txt` |
| Windows | `%LOCALAPPDATA%\com.yats.app\logs\hardware_audit.txt` |

## 11. 設定ファイル

設定は JSON 形式で自動保存されます。手で編集することもできますが、YATS を終了した状態で編集してください。ファイルを削除すると、既定の設定で再生成されます（キー割り当ても初期状態に戻ります）。

| OS | 設定ファイルの場所 |
|---|---|
| Linux | `~/.config/com.yats.app/config.json` |
| Windows | `%APPDATA%\com.yats.app\config.json` |

## 12. 既知の制限

- **Linux のパームリジェクションは発展途上**です。デバイスや使い方によっては、意図した操作が抑止されたり、タイピング中の誤発火が残ったりする場合があります
- **Wayland 環境（Linux）**: ウィンドウ操作（`xdotool` を使用する機能）は動作しない場合があります。リマップやスクロールは動作します
- **Windows の接触検出**は Precision Touchpad 搭載機種でのみ使えます。それ以外のデバイスでは移動検出を使ってください
- **権限（Linux）**: デバイスへのアクセス権限が不足していると、キーのリマップが機能しません。第3章の必須要件を確認してください
